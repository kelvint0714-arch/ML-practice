# Day 24 概念精讲：用消融回答“复杂度从哪里来”

## 1. 消融不是普通调参

调参常问“哪组设置分数最低”；消融问“删除或替换一个组件后，结果怎样变化”。它强调控制变量和机制解释。

一个最小消融矩阵可以包含：

| 方案 | 树 | MLP | 二层学习 | 原始特征直通 |
|---|---:|---:|---:|---:|
| tree only | 是 | 否 | 否 | 否 |
| MLP only | 否 | 是 | 否 | 否 |
| simple mean | 是 | 是 | 否 | 否 |
| stack tree only | 是 | 否 | 是 | 否 |
| stack tree + MLP | 是 | 是 | 是 | 否 |

每行必须复用同一数据、划分、基础模型参数和指标。
最后两行之间唯一新增组件是 MLP；`stack tree only` 仍通过树的 OOF
预测训练 Ridge 二层，所以它与直接树模型不是同一个方案。

## 2. 基准和差值

以预先固定的传统模型为基准：

\[
\Delta RMSE=RMSE_{\text{variant}}-RMSE_{\text{baseline}}
\]

- `ΔRMSE < 0`：当前方案 RMSE 更低；
- `ΔRMSE > 0`：当前方案 RMSE 更高；
- 接近 0：差异可能小于随机波动。

差值没有自动携带显著性。必须结合多种子或多划分结果。

## 3. 一次只改一项

若比较 `stack tree only` 与 `stack tree + MLP`，唯一变化应是 MLP。不能同时更换：

- 基础模型超参数；
- 内部折数；
- 外部划分；
- 输入特征版本；
- 随机种子集合。

本日两个 stack 还必须共享完全相同的 Bemis–Murcko scaffold split 列表。

否则无法将变化归因于直通机制。

## 4. 复杂度也要进入结果表

一个方案不只由 RMSE 描述，还包括：

- 需要拟合的模型次数；
- 墙钟耗时；
- 内存与特征维数；
- 调试和复现难度；
- 解释与部署成本。

若 stacking 只获得微小且不稳定的改善，简单平均或单模型可能更合理。

## 5. 负结果是有效证据

“完整 stack 没有超过简单平均”不是失败，而是回答了研究问题：在当前协议和输入下，学习组合权重没有提供可验证收益。保留完整消融矩阵比只展示最好一行更可信。

## 6. 特征组消融与真实下游任务

真实数据到达后可按来源比较：

```text
配方
配方 + 固化
配方 + 固化 + 基材/表面
再加预测时可获得的理化性质
```

所有字段都必须由领域团队确认且在预测时可获得。不能从不同论文中拼造数值，也不能把 ESOL 指纹消融写成下游任务字段结论。

## 证据边界

今天冻结的是“候选方案”，不是普遍最佳模型。测试集继续封存；一次 ESOL 验证只用于学习消融方法。
