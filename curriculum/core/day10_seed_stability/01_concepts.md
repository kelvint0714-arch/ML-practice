# Day 10 概念讲义：多随机种子稳定性

## 学习目标

本日关注“同一份数据、同一个模型配置，仅改变随机过程”时结果是否稳定。完成后，你应能：

- 找出模型中的随机性来源；
- 运行预先声明的一组种子；
- 区分逐次结果、均值、标准差、最小值与最大值；
- 验证相同种子是否可复现；
- 说明该实验没有覆盖哪些不确定性。

## 1. 随机种子不是魔法数字

计算机通常使用伪随机数生成器。给定初始状态（seed），同一实现便能重复产生相同的随机序列。随机森林中的 seed 可能控制：

1. 每棵树看到的 bootstrap 样本；
2. 每个节点候选特征的抽取；
3. 其他库内部明确绑定到 `random_state` 的随机步骤。

随机种子不改变数据的科学含义，也不会让一个有缺陷的验证协议变正确。

## 2. 多种子实验的控制变量

如果目的是测量模型自身随机波动，下列内容必须固定：

| 固定项 | 例子 |
|---|---|
| 训练与验证行 | 使用同一组索引 |
| 特征和标签 | 相同列、相同标签尺度 |
| 模型超参数 | 树数、叶节点大小、特征抽样规则 |
| 指标 | 同一 MAE、RMSE、R² 实现 |
| 软件环境 | 记录 Python 与 sklearn 版本 |

唯一主动变化的是模型 `random_state`。

## 3. 为什么种子必须提前声明

如果先运行很多种子，再只保留成绩最好的一次，相当于偷偷把 seed 当作调参候选，而且隐藏了不利证据。规范做法是先写下种子集合，例如：

```python
SEEDS = [0, 1, 2, 3, 4, 42, 100, 2026]
```

运行后保存全部八行。

## 4. 五种汇报量

| 量 | 含义 | 不能说明什么 |
|---|---|---|
| 每个 seed 的分数 | 每次真实运行证据 | 单独一次不能代表稳定性 |
| mean | 中心水平 | 不描述波动 |
| std | 种子间波动 | 不等于实验测量误差 |
| min / max | 观察范围与异常检查 | 不等于总体理论边界 |
| 重复同一 seed 的差值 | 当前环境下的复现检查 | 不保证跨版本逐位一致 |

“均值 ± 标准差”必须说明它来自多少个 seed、固定了什么划分。

## 5. 模型随机性与划分随机性

这两种实验不能混称：

```text
模型随机性：
固定 train/valid 行
只改变 RandomForestRegressor.random_state

划分随机性：
重新生成 train/valid 或 K 折
模型种子可以固定，也可以按预先声明规则变化
```

若两者同时改变，得到的是综合波动，不能再把差异归因于单一来源。

## 6. 可复现不等于完全相同

在相同环境中，相同 seed 通常得到一致结果；但以下变化可能影响结果：

- sklearn、NumPy 或编译库版本改变；
- 并行算法、硬件和数值精度不同；
- 输入行顺序变化；
- 默认参数在新版本中改变；
- 数据或特征缓存改变。

因此还要记录环境、输入版本和完整参数，而不只是 seed。

## 7. 证据边界

固定划分的多 seed 实验只能描述：

> 当前数据、当前划分、当前特征、当前模型配置下，由模型随机过程带来的观察波动。

它不能直接代表：

- 换一组训练样本后的波动；
- 湿度、温度或仪器造成的测量误差；
- ESOL 与下游任务任务之间的迁移误差；
- 未见化学空间上的泛化能力。
