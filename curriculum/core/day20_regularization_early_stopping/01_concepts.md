# Day 20 概念精讲：正则化与早停

## 学习目标

- 区分 L2 正则化和早停；
- 区分训练损失、内部早停验证和外部验证；
- 能从训练—验证差距识别过拟合或欠拟合迹象；
- 知道候选方案必须在看结果前固定。

## 1. L2 正则化约束权重

MLP 的优化目标可以简化写成：

\[
\text{objective}=\text{data loss}+\alpha\sum_j w_j^2
\]

第一项要求预测接近标签，第二项惩罚过大的权重。`alpha` 越大，约束通常越强，但不保证验证性能单调改善：

- 太小：模型可能记住训练细节；
- 适中：可能降低方差；
- 太大：模型可能欠拟合。

因此 `alpha` 是要通过训练内协议比较的超参数，不是“越大越高级”。

## 2. 早停解决的是训练时机

`early_stopping=True` 时，`MLPRegressor` 从传入的训练数据内部再留出一部分。每轮训练后观察内部验证分数；若连续 `n_iter_no_change` 轮没有足够改善，就提前结束。

```text
外部训练集
├── 内部更新子集：用于梯度更新
└── 内部早停子集：用于决定何时停止

外部验证集：只比较冻结候选
测试集：继续封存
```

早停减少无效迭代并可能缓解过拟合，但它依赖内部随机划分和样本量，不是自动最优保证。

## 3. 三条曲线/分数不能混用

| 对象 | 数据来源 | 用途 |
|---|---|---|
| `loss_curve_` | 内部训练数据 | 观察优化过程 |
| `validation_scores_` | 训练集内部留出部分 | 逐轮 `R²` 早停监控 |
| 外部 valid RMSE | 独立外部验证 | 比较预先固定方案 |

`loss_curve_` 不是 RMSE 数组，也不是外部验证曲线。它记录 MLP 内部优化损失。
对回归器而言，`validation_scores_` 和 `best_validation_score_` 是 `R²`；
数值越大越好，不能把它们命名或解释成内部 RMSE。

### sklearn Pipeline 的内部隔离边界

本日教程使用 `imputer → scaler → MLPRegressor(early_stopping=True)`。
Pipeline 先用全部外部 `X_train` 拟合插补器和缩放器，之后 MLP 才在已经变换的
训练矩阵中切内部早停集。因此：

- 外部 valid/test 没有泄漏进训练；
- 但插补和缩放统计量见过内部早停集，内部早停分数不是严格嵌套验证证据；
- 若要严格隔离，应先显式切 `subtrain/internal-valid`，只在 subtrain 拟合预处理，
  再用可审计训练循环在 internal-valid 上选择停止点。

## 4. 控制变量

今天推荐只比较两个预先声明方案：

- 弱正则、不开早停；
- 较强正则、开启内部早停。

这种比较同时改变了两个机制，所以只能回答“整套方案哪一个在当前协议下表现如何”，不能把差异全部归因给 `alpha`。若要严格判断正则化和早停各自贡献，需要 Day 24 式的 2×2 消融。

## 5. 怎样判断现象

| 现象 | 可能解释 | 下一步 |
|---|---|---|
| train 好、valid 差 | 过拟合 | 增强约束、更多数据、稳定性检查 |
| train/valid 都差 | 欠拟合或优化失败 | 检查损失、学习率、容量 |
| 很早停止且两边都差 | 早停过早 | 检查内部样本量和耐心值 |
| 达到 `max_iter` | 可能未收敛 | 看曲线末端与警告 |

这些都是诊断线索，不是单凭一个数就能确定的因果结论。

## 证据边界

只在外部训练数据内部使用早停标签；外部验证用于比较冻结方案；测试集不参与。
同时披露预处理统计量见过内部早停样本这一 sklearn 限制。ESOL 的任何观察仍只属于公开 `logS` 练习。
