# Day 27.1：论文描述、数据字典和数据行是三种对象

## 1. 论文描述

论文告诉你作者研究了什么，但不保证所有实现细节、原始数据和许可都公开。来源标识用于追溯，不能替代数据审计。

## 2. 数据字典

数据字典定义“每一列是什么意思”，本身不包含训练样本。

| 项目 | 回答的问题 |
|---|---|
| name | 字段叫什么？ |
| role | 输入、目标、条件、分组还是标识？ |
| dtype | 数值、类别、文本还是布尔？ |
| unit | 单位是什么？ |
| source | 定义来自哪里？ |
| missing_rule | 缺失怎样解释？ |
| visibility | 训练、query、评价时是否可见？ |

## 3. 数据行

数据行是某个样本的实际记录。字段定义完成不代表已经获得任何样本，更不代表能够训练。

## 4. 合并来源的六项检查

1. 一行是否代表同一种对象；
2. 目标含义是否一致；
3. 单位是否可合法转换；
4. 测量或标注流程是否可比；
5. 特征是否在同一阶段可见；
6. 许可是否允许使用和再分发。

任一关键项未知时，默认不合并。

## 5. 防止标签泄漏

数据字典应显式标记字段可见性。测试标签、未来信息、事后统计或由目标直接计算的字段不能作为普通输入。

## 6. 今天的停止点

今天只形成来源映射和字段定义，不下载拼表、不训练模型、不填造缺失信息。
