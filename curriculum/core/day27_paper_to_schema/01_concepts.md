# Day 27 概念精讲：从论文证据到字段候选

> **重要：本日所有 schema、字段值和表格行都是讨论模板或文献映射示例，不是真实粘合剂实验数据。**

## 1. 三层对象不要混淆

1. **论文描述**：作者在特定体系和试验中使用的变量；
2. **候选字段**：受论文启发、等待化学组确认的 schema 项；
3. **本组真实数据**：有来源、权限、单位和实验追溯的记录。

论文中出现一个变量，不意味着它自动成为本项目必填列，更不意味着已获得该论文的可训练原始数据。

## 2. 字段映射的五个层次

| 层次 | 典型问题 |
|---|---|
| 身份 | 一行代表配方、试样还是重复？ |
| 配方 | 组分是谁、多少、用什么基准？ |
| 工艺/接头 | 固化、基材、表面和胶层如何定义？ |
| 标签 | 性能名称、单位、标准、环境是什么？ |
| 质量/权限 | 批次、重复、缺失原因、可否建模/公开？ |

只记录“强度”而缺少测试方法和单位，无法形成可靠标签。

## 3. 通用类别与体系专用字段

通用的是字段类别，例如样品编号、组分身份、用量、固化条件、基材、测试方法和来源。

体系专用的是具体化学变量，例如：

- 环氧：环氧当量、胺/环氧比；
- 聚氨酯：NCO 相关参数、木材含水率；
- 特定测试：低温冲击剥离条件。

最终体系未确认前，不应把所有论文变量设成强制必填。

## 4. 为什么不同论文不能直接纵向拼表

即使标签都包含“强度”，也可能在以下方面不同：

- 化学体系；
- 基材和表面处理；
- 试样几何；
- 测试标准与加载方式；
- 温湿度和单位；
- 一行的统计含义。

直接拼接会让模型学习来源差异，目标物理含义也可能不一致。

## 5. DOI 能证明什么

DOI 是文献溯源标识，可证明字段映射参考了哪篇工作。它不能自动证明：

- 原始数据公开；
- 许可允许再分发或建模；
- 本组复现了论文；
- 论文结果是本组结果。

## 6. schema 状态

建议使用状态机：

```text
draft → chemistry review → pilot rows → frozen v1.0 → versioned revisions
```

`draft-v1.0` 仍是讨论稿。字段冻结前先确定体系、行定义和首要目标。

## 7. 今天的停止点

今天不训练模型、不下载拼接论文数值、不填造样例性能。产物应是“字段依据、待确认问题和不可比较记录”。
