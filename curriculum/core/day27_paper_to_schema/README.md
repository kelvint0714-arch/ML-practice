## 今天为什么学

论文中的“输入”“目标”和“数据集”经常写在不同段落。直接抄一个变量名不足以复现任务；必须同时记录定义、单位、来源、可用阶段和评价协议。

## 前置条件

- 完成 Day 26；
- 能区分特征、标签、条件和元数据；
- 知道论文描述不等于已经获得原始数据；
- 今天不训练模型。

## 今日产出

1. 一张来源映射表；
2. 一份字段数据字典；
3. 一张来源合并检查表；
4. 一份缺失信息清单。

## 核心概念

字段至少需要：名称、角色、数据类型、单位、来源、缺失规则和可见阶段。只有标签定义、单位、样本语义和许可都兼容时，才讨论合并来源。

## 分步骤任务

1. 记录来源、任务类型和样本定义；
2. 分开输入、目标、条件和分组字段；
3. 为每个字段补类型、单位和缺失规则；
4. 标记 train/query/evaluation 阶段的可见性；
5. 检查不同来源能否合并；
6. 把未知信息写成 pending，不自行猜测。

## 核心代码

~~~python
field_dictionary = {
    "feature_1": {
        "role": "input",
        "dtype": "float",
        "unit": "documented unit",
        "missing_rule": "pending",
        "visible_during_query": True,
    }
}
~~~

## 常见错误

- DOI 或链接存在，就假定数据可下载和再分发；
- 同名目标不检查单位、测量方式和样本定义；
- 把测试集标签写成普通可见字段；
- 用模型方便性代替字段含义；
- 把未知值填成 0。

## 完成标准

- [ ] 输入、目标、条件和分组字段已分开；
- [ ] 每个字段有类型、单位或明确的 pending；
- [ ] 标签可见性规则清楚；
- [ ] 没有虚构数据值或许可；
- [ ] 能解释两个来源为何能或不能合并。

## 自测问题

1. 字段名相同为什么仍可能不可合并？
2. 数据字典和训练数据有什么区别？
3. 哪些字段在候选选择时必须隐藏？
4. 未知单位应该怎样记录？
5. 来源链接能证明什么、不能证明什么？
