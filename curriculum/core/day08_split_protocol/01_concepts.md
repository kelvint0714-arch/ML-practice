# Day 8.1：数据划分决定一个分数能说明什么

同一个模型、同一个指标，如果评价数据的角色不同，证据含义也不同。今天的重点不是提高分数，而是防止信息从 validation 或 test 流回训练过程。

## 1. 三个 split 的职责

| split | 允许做什么 | 不允许做什么 |
|---|---|---|
| train | 拟合模型参数和预处理器 | 代替未见数据评价 |
| validation | 比较候选、观察过拟合、选超参数 | 调用模型或 scaler 的 `fit` |
| test | 方案冻结后的最终评价 | 日常调参、反复比较 |

数据名称本身不保证职责正确。把 test 变量改名成 validation，却继续用它反复选择模型，实质没有改变。

## 2. 哪些对象都会“学习”

不仅预测模型需要 `fit`，下列对象也可能从数据学习信息：

- `StandardScaler` 的均值和标准差；
- 缺失值填补器的中位数；
- 特征选择器；
- PCA；
- 目标编码器；
- 文本词表；
- 神经网络早停规则。

正确原则：

```text
任何会从数据估计数值或规则的步骤
只能在对应训练范围内 fit
```

然后对 validation/test 只调用 `transform` 或 `predict`。

## 3. 什么是数据泄漏

泄漏指模型开发直接或间接使用了部署时不应获得的信息。

常见例子：

```text
在全数据上拟合 scaler
先看 test 分数再改参数
同一分子同时在 train 和 valid
用 validation 标签构造训练特征
按行随机划分同一实验批次的重复测量
```

泄漏通常让评价过于乐观，但也可能产生难以预测的偏差。它不是简单的“分数一定特别高”。

## 4. 划分单位必须对应研究问题

一行不一定等于独立对象。例如未来粘合剂数据可能有：

- 同一配方的重复测量；
- 同一分子骨架的多个衍生物；
- 同一实验批次的多条记录；
- 同一论文来源的多个条件。

若相关行被拆到不同 split，模型可能只是在识别近重复项。划分单位应根据实际泛化问题选择，而不是永远按行随机。

## 5. ESOL 为什么使用 scaffold split

scaffold split 尝试按分子骨架组织划分，使验证分子与训练分子的核心结构更有区别。这比普通随机行划分更接近“面对新骨架”的挑战。

但 scaffold split 也不是绝对保证：

- 具体实现和分子标准化会影响骨架；
- 不同骨架仍可能有相似局部结构；
- 单次 split 仍有偶然性；
- 精确 SMILES 无重叠不等于所有结构关系独立。

## 6. 精确 ID 重叠检查

把每个 split 的 ID 转成集合：

```text
train_ids & valid_ids
```

若交集非空，说明至少有完全相同 ID 同时出现。

它能发现：

- 相同字符串 ID；
- 明确重复主键。

它不能发现：

- 不同写法表示同一实体；
- 盐型、互变异构体或标准化差异；
- 近重复分子；
- 同一配方的不同名称；
- 同一实验批次造成的关联。

## 7. shape 与有限值检查

对 train、validation 至少检查：

```text
X 行数 == y 长度 == ID 数
X 特征列数一致
X 和 y 全部有限
样本数非零
```

对本日封存的 test 只检查：

```text
X 行数 == ID 数
X 特征列数一致
X 全部有限
样本数非零
```

代码不访问 `test_dataset.y`。这属于输入契约，也把测试集权限落实为
可审计的代码边界。它不能证明标签正确，但能尽早阻止明显坏数据进入模型。

## 8. validation 也会被“用旧”

即使从不看 test，反复在同一个 validation 上尝试几百个方案，也会逐渐选择出偶然适合该 validation 的模型。

因此要记录：

- 尝试了哪些候选；
- 候选是否预先设定；
- validation 被查看多少次；
- 何时冻结方案。

Day 9–13 会引入交叉验证和更严格比较。

## 9. 当前 ESOL test 的历史边界

旧版实验已经查看过当前 ESOL test。因此：

- 不能假装忘记并重新称它为严格未见；
- Day 8 不产生新的 test 预测；
- 课程开发继续使用 train/validation；
- 真正最终无偏证据需要预先设计新的外层 holdout 或嵌套协议。

诚实记录数据暴露比删除旧输出更重要。

## 10. 一份可执行的测试集政策

```text
1. 开发阶段只使用 train 与 validation。
2. 所有预处理和模型只在 train 或训练折内 fit。
3. 记录每次候选比较。
4. 方案、指标和代码冻结后，才执行最终评价。
5. 已暴露的原 test 不重新包装成严格未见。
6. 若要新的无偏结论，预先建立新的外层评价协议。
```
