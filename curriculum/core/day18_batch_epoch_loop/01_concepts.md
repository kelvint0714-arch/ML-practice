# Day 18 概念讲义：Batch、Iteration 与 Epoch

## 学习目标

今天使用 scikit-learn `MLPRegressor.partial_fit()` 显式观察训练循环。完成后你应能：

- 区分 batch、iteration 和 epoch；
- 计算每个 epoch 的批次数；
- 在每个 epoch 开始时只打乱训练行；
- 确保验证数据从不更新模型；
- 保存训练与验证 RMSE 曲线；
- 解释曲线分离与早停动机。

## 1. 三个计数单位

| 名称 | 本课程定义 |
|---|---|
| Batch | 一次参数更新使用的一小组训练样本 |
| Iteration / update | 对一个 batch 调用一次 `partial_fit()` |
| Epoch | 所有训练样本大致被遍历一次 |

库文档中的计数可能有不同细节，因此研究记录应写明自己的定义。

## 2. 批次数

若训练样本数 `n=100`、批大小 `32`：

```text
批1：32
批2：32
批3：32
批4：4
```

批次数：

```text
ceil(100 / 32) = 4
```

最后一个小批不应被无声丢弃，除非协议明确要求且记录原因。

## 3. 为什么打乱训练顺序

每个 epoch 生成新的训练索引排列，可以避免模型总按同一固定顺序接收样本。打乱：

- 只作用于训练行；
- `X_train` 与 `y_train` 必须使用同一索引；
- 不能让验证行进入排列；
- 固定 RNG seed 后可复现整个顺序序列。

## 4. `partial_fit()` 与重新建模

```python
model.partial_fit(X_batch, y_batch)
```

会在当前参数基础上继续更新。

错误做法：

```python
for batch in batches:
    model = MLPRegressor(...)   # 每批权重清零
    model.partial_fit(...)
```

模型必须在循环外创建一次。

## 5. 训练与验证边界

训练数据：

- 拟合缩放器；
- 进入 `partial_fit()`；
- 用于训练 RMSE。

验证数据：

- 只用训练缩放器 `transform`；
- 只进入 `predict()`；
- 用于验证 RMSE；
- 绝不进入 `partial_fit()`。

验证标签也不能用于梯度更新。

## 6. 每个 Epoch 记录什么

至少记录：

```text
epoch
n_updates
train_rmse
valid_rmse
```

训练曲线帮助判断优化是否进行；验证曲线提供独立开发证据。只保存最后一轮会隐藏：

- 前期是否发散；
- 最佳验证轮次；
- 训练/验证何时开始分离；
- 是否存在异常跳变。

## 7. 曲线如何解释

| 现象 | 可能解释 | 下一步检查 |
|---|---|---|
| 两条都下降 | 正在学习，暂未见明显分离 | 继续按预设 epoch 观察 |
| 训练降、验证升 | 可能过拟合 | Day 20 学正则化与早停 |
| 两条都不降 | 学习率、尺度或模型容量问题 | 检查缩放和警告 |
| 两条剧烈震荡 | 学习率可能过大或 batch 太小 | 固定其他条件做对照 |

这些是诊断线索，不是单凭图形就能证明原因。

## 8. 最佳 epoch 也是选择

如果根据验证曲线选取最佳 epoch，验证集已参与模型选择。可以这样做，但必须：

- 预先说明早停规则；
- 保存完整曲线；
- 不把最佳验证分数当严格测试结果；
- 最终仍需独立评价协议。

本日只观察曲线，Day 20 专门学习早停。
