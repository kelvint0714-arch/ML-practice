# Day 28.1：模型卡不是宣传页

## 1. 模型卡的用途

模型卡让读者不打开全部代码也能知道模型如何训练、如何选择、怎样评价以及什么时候不应使用。

## 2. 最低内容

| 部分 | 必须回答 |
|---|---|
| 任务 | 输入、目标、任务类型是什么？ |
| 数据 | 来源、样本定义和划分是什么？ |
| 模型 | 基线、候选和参数怎样冻结？ |
| 评价 | 指标、重复和选择规则是什么？ |
| 结果 | 均值、波动和失败模式是什么？ |
| 限制 | 哪些数据或场景没有覆盖？ |
| 版本 | 代码、环境和生成日期是什么？ |

## 3. 验证与测试

验证数据用于模型选择；测试数据用于冻结方案后的最终检查。如果 test 参与选择，就不能再把它描述为未见评价。

## 4. 公平比较

模型必须使用相同样本范围、划分和指标。若某个模型使用额外输入，需要明确记录，不能只比较最后一列分数。

## 5. 有限结论

推荐句式：

> 在已声明的数据、划分、输入和指标下，模型 A 的交叉验证 RMSE 低于基线 B；当前证据不支持外推到其他数据分布。

## 6. 下一步

下一步应修复最重要的证据缺口，例如样本覆盖、分组划分、校准或复现，而不是默认换更复杂的模型。
