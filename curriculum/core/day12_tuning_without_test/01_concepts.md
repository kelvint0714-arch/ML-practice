# Day 12 概念讲义：不偷看测试集的调参

## 学习目标

本日不是追求“最高分”，而是建立可信的参数选择程序。完成后你应能：

- 区分超参数与模型拟合参数；
- 说明训练内交叉验证、外部验证和测试集的职责；
- 用 Pipeline 保证每个候选、每一折的预处理不泄漏；
- 读懂 `GridSearchCV` 的候选结果和负评分约定；
- 解释为什么调参结果不能直接冒充无偏性能估计。

## 1. 参数有两类

| 类型 | 何时确定 | Ridge 例子 |
|---|---|---|
| 超参数 | `fit()` 前由研究者或搜索程序指定 | `alpha` |
| 模型参数 | `fit()` 从训练数据学到 | `coef_`、`intercept_` |

`alpha` 越大，L2 惩罚通常越强，系数会被更明显地压向零。哪一个 `alpha` 合适要用允许的开发数据选择，而不是看最终测试分数。

## 2. 三层数据职责

```text
训练区域内部 K 折
    用途：比较预先声明的候选超参数
            ↓ 参数冻结
外部验证集
    用途：检查冻结方案在独立开发集上的表现
            ↓ 完整方案冻结
最终测试集
    用途：按协议一次性评估，不用于继续挑参数
```

当前 ESOL 历史测试分数已经暴露，因此课程不会把它重新包装成严格未见证据。Day 12 仍只练习训练内 CV 与外部验证。

## 3. 为什么不能用测试集选参数

假设比较 100 个候选，即使它们真实能力相同，也可能有一个候选因随机波动在测试集上“碰巧最好”。若保留它，测试集已经参与选择，最终分数会偏乐观。

测试集不是免费查询接口。每次依据测试反馈修改方案，都会消耗其独立性。

## 4. Pipeline 为什么必须进入搜索

错误：

```text
全部训练区域先 fit scaler
→ 再把缩放结果送入 K 折搜索
```

此时每一折的验证部分已参与缩放统计量。

正确：

```text
GridSearchCV 接收原始 X_train 和完整 Pipeline
→ 每个候选、每一折 clone Pipeline
→ 只在该折训练部分拟合填补器、缩放器和 Ridge
```

## 5. 参数网格

```python
param_grid = {
    "ridge__alpha": [0.01, 0.1, 1.0, 10.0, 100.0],
}
```

双下划线表示：

```text
Pipeline 步骤名__该步骤参数名
ridge__alpha
```

候选表应在看结果前声明。可以基于先验知识设计对数尺度候选，但不能运行后悄悄删除不喜欢的行。

## 6. scikit-learn 的负评分

scikit-learn 的选择接口统一遵循“分数越大越好”。RMSE 本来越小越好，因此评分器返回：

```text
neg_root_mean_squared_error = -RMSE
```

例如真实 RMSE 为 `0.8`，内部评分为 `-0.8`；`-0.8` 比 `-1.2` 大，所以前者更好。展示时通常取负号恢复正 RMSE。

## 7. `best_params_` 与 `best_estimator_`

- `best_params_`：被训练内 CV 选中的参数字典；
- `best_estimator_`：默认 `refit=True` 时，用最佳参数在完整 `X_train` 上重新拟合的完整 Pipeline；
- `cv_results_`：所有候选的逐折和汇总信息，必须保留；
- `best_score_`：最佳候选的训练内 CV 评分，不是外部验证分数。

## 8. 调参偏差与嵌套交叉验证

同一组 CV 折既参与选择候选，又被用来描述所选候选的表现，所以 `best_score_` 对“选择后的方案”可能偏乐观。Day 12 用独立外部验证做一次检查。

若没有外部验证、又要同时调参与获得更接近无偏的性能估计，应使用嵌套交叉验证：

```text
外层折：估计性能
内层折：选择参数
```

本日只认识边界，不实现完整嵌套 CV。
