# 统一实验协议

这份协议从 Day 1 一直适用到 Day 28。任何模型结果只有在协议一致时才可以放进同一张比较表。

## 一次实验必须记录什么

- 数据集名称与版本；
- 一行数据代表什么；
- 特征类型和维数；
- 目标名称、单位与是否变换；
- train/validation/test 的样本数和划分方法；
- 模型名称、全部超参数与随机种子；
- MAE、RMSE、R²；
- 训练时间和运行环境；
- 是否使用了测试集；
- Git commit 或工作树状态。

## 数据使用规则

```text
训练集：拟合模型和预处理器
验证集：选择候选模型和超参数
测试集：方案冻结后只做最终检查
```

当前 ESOL 的旧 test split 已在历史 Notebook 中暴露，因此核心课程不把它包装成严格未见的最终证据。Day 2–28 继续使用 train/validation 完成学习与比较。

## 预处理防泄漏

错误流程：

```python
scaler.fit(all_X)
```

这里的 `all_X` 如果包含验证或测试样本，缩放器已经看到了不该看到的信息。

正确思路：

```python
scaler.fit(X_train)
X_train_scaled = scaler.transform(X_train)
X_valid_scaled = scaler.transform(X_valid)
```

更推荐把预处理和模型放入 `Pipeline`，让交叉验证自动在每个训练折内拟合预处理器。

## 公平比较清单

只有下面问题全部回答“是”，两行模型结果才可以直接比较：

- 输入样本相同吗？
- 特征信息相同吗？
- 目标空间和单位相同吗？
- 数据划分相同吗？
- 指标实现相同吗？
- 是否都没有使用测试标签调参？
- 随机模型是否报告了重复运行？
- 是否都保留训练时间和参数？

## 指标解释

- MAE 越小越好，表示绝对误差的平均水平；
- RMSE 越小越好，会更重地惩罚大误差；
- R² 越大通常越好，但小于 0 不一定表示代码出错；
- RMSE 和 MAE 不是“准确率”；
- 单次指标不代表稳定性，应结合均值和标准差。

## 结果边界的标准写法

推荐写法：

> 在固定的 ESOL scaffold train/validation 划分、相同 ECFP 输入和统一指标下，模型 A 的验证 RMSE 低于模型 B。该结果是公开数据上的算法练习，尚不能说明模型 A 在真实下游任务数据上更优。

不推荐写法：

> 我们已经证明模型 A 最适合下游任务预测。

后一句超出了当前数据和实验能够支持的范围。
