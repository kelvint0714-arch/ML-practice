# Day 35.1：粘合剂 GNN 不是“有名称就能画图”

## 1. 先区分四种对象

| 对象 | 例子 | 能否直接等同 |
|---|---|---|
| 化学名称 | 某树脂或固化剂的名称 | 不能自动等同结构 |
| 分子结构 | 经确认的 SMILES、SDF、mol 文件 | 可用于构造单分子图 |
| 配方 | 多个组分、配比和添加剂 | 不能自动等同单分子图 |
| 试样与性能 | 固化、基材、测试条件下的测量 | 是最终样本/标签语境 |

商业名称、简称或“环氧”大类不能可靠推出唯一结构。自己在网上猜一个 SMILES，会把未知事实伪装成精确输入。

## 2. “结构表示”具体是什么

结构表示是能明确构造原子和键的数据，例如：

- 经领域人员确认的 SMILES；
- SDF/MOL 文件；
- 具有来源、版本和物质对应关系的结构数据库记录。

一个合格结构字段还需要：

1. 结构属于哪个组分；
2. 来源可追溯；
3. 盐、混合物、重复单元和聚合物怎样处理；
4. 是否由化学组确认；
5. 缺失原因是什么。

“是否有结构”不只是 Yes/No，而是一条数据血缘问题。

## 3. 为什么单个分子图不能代表粘合剂配方

粘合剂常包含主树脂、固化剂、促进剂、填料或其他添加剂。性能还受配比、固化温度/时间、基材、表面处理和测试标准影响。

```text
单个组分结构
≠ 多组分配方
≠ 固化后的网络
≠ 特定测试条件下的粘接性能
```

若未来做多分支模型，可能是：

```text
各组分结构 → 共享或独立 GNN ┐
配比/工艺/测试 → 表格编码器  ├→ 融合 → 性能
传统描述符/基线 ────────────┘
```

但这只是候选架构，必须先明确一行样本、组分对应和信息可用性。

## 4. v0.3 模板现在有什么

仓库中的 v0.3 是字段讨论稿。核心表包含样品编号、体系、主树脂/固化剂名称、分子量、官能团、配比、黏度、Tg、固化条件和实测性能字段。

当前事实：

- 数据行数为 0；
- 实测性能标签数为 0；
- 没有经确认的 SMILES、SDF 或结构文件字段；
- 没有结构来源与审核状态；
- 权限和真实项目数据尚未进入公开仓库。

字段名存在只说明接口存在，不说明已有数据。

## 5. Go/No-Go 的七项门槛

| 门槛 | 通过标准 |
|---|---|
| 样本定义 | 一行代表配方、试样还是重复测量已冻结 |
| 结构对象 | 明确图代表哪个组分或组合 |
| 结构来源 | SMILES/SDF 可追溯且经化学组确认 |
| 多组分表示 | 配比、多个组分和聚合物处理方式明确 |
| 目标协议 | 一个主要性能、单位和测试方法一致 |
| 数据/划分 | 有足量独立配方，重复和批次不跨分组 |
| 权限/基线 | 获准使用，且表格传统模型基线已实际运行 |

不是满足其中两三项就算 Go。关键门槛未知时，默认 No-Go。

## 6. 三种决策

### Go

所有关键门槛通过，可以按冻结协议开始公开/受控范围内的 GNN 对照。

### 补数据后 Go

研究问题合理，但结构覆盖率、样本关系或标签协议尚未达到门槛。下一步是补数据和确认，不是先训练。

### No-Go

图对象不合理、结构不可得、权限不允许，或 GNN不能回答当前问题。继续表格基线可能是正确科研选择。

当前 v0.3 的自动评审只能得到 **No-Go（证据不足）**。未来真实数据到达后必须重新人工评审，不能把本日结论永久化。

## 7. 公平比较最低要求

未来若门槛通过，至少比较：

- Dummy；
- 表格 Ridge / RF / Boosting；
- 可用时的 ECFP＋传统模型或 MLP；
- 纯结构 GNN；
- 结构＋配方/工艺融合；
- 去掉结构、去掉工艺的消融。

所有模型必须使用相同样本范围、分组划分和指标。GNN 若使用额外信息，不能与缺少这些信息的弱基线直接宣称公平胜出。
