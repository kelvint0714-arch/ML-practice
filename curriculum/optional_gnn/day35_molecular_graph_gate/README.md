# Day 35：分子图与粘合剂 GNN 启用评审

## 今天为什么学

完成公开图任务后，最后一步不是立刻把 GNN 套到粘合剂上，而是判断项目有没有正确的图对象、结构信息和足够数据。

## 前置条件

- 已完成 Day 29–34；
- Day 28 的粘合剂数据接入清单已经存在；
- 化学组能够确认结构字段；
- 传统表格与 MLP 基线已经冻结。

## 今日产出

- 一份 `gnn_go_no_go.md`；
- 一张“样本—组分—结构—配方—性能”关系图；
- ECFP 与 GNN 公平比较方案；
- 最终决定：现在启动、补数据后启动，或暂不启动。

## 核心概念：必须先回答的项目问题

| 问题 | 为什么重要 |
|---|---|
| 一行代表配方还是单个分子？ | 决定一张图代表什么 |
| 一个配方有几个组分？ | 单图可能无法直接表示多组分体系 |
| 每个组分有可靠 SMILES/SDF 吗？ | 没有结构就不能构造可信分子图 |
| 配比、固化和测试条件放在哪里？ | 它们通常不是原子图字段 |
| 样本量和结构多样性有多少？ | 决定复杂模型是否可训练 |
| 目标和测试方法是否统一？ | 标签不可比时任何模型都不可信 |

## 三种可能架构

### 方案 A：暂时只做表格模型

```text
配方比例 + 理化性质 + 工艺 + 测试条件
→ RF / Boosting / MLP
→ 性能
```

适合结构缺失或样本很少的阶段。

### 方案 B：单组分结构模型

```text
可靠分子结构
→ GNN
→ 单分子性质
```

只适合目标确实属于单个分子时，不能自动代表完整粘合剂配方。

### 方案 C：多分支融合

```text
各组分结构 → GNN 表征 ┐
配方/工艺/测试 → MLP ├→ 融合 → 性能
传统描述符/树模型 ───┘
```

这是可能的长期模式，但需要同一样本同时具备结构、配方、工艺和性能。

## 公平比较计划

至少保留：

1. Dummy；
2. 表格 Ridge/随机森林/Boosting；
3. ECFP＋MLP；
4. 纯 GNN；
5. 结构＋表格融合；
6. 去掉结构或去掉工艺的消融实验。

所有模型使用同一分组划分，不能让同一配方的重复测量跨到训练和验证两边。

## 分步骤任务

1. 检查数据表中的结构字段及来源；
2. 随机抽查结构能否被 RDKit 解析；
3. 统计有效结构率和缺失原因；
4. 明确多组分如何表示；
5. 估计每个划分中的独立配方数量；
6. 写出表格基线和 GNN 的公平协议；
7. 由导师和化学组确认是否启动。

## 常见错误

- 把供应商名称自动当成分子结构；
- 自己在网上猜商业配方的 SMILES；
- 一个组分有结构就声称完整配方有图；
- GNN 使用额外信息，却与较弱表格基线直接比较；
- 忽略重复实验和批次造成的泄漏。

## 完成标准

- [ ] 图的含义由领域人员确认；
- [ ] 结构来源可追溯；
- [ ] 多组分和工艺的处理方式明确；
- [ ] 公平基线与划分协议写清楚；
- [ ] 最终决定有证据，不因“GNN更高级”而默认启动。
