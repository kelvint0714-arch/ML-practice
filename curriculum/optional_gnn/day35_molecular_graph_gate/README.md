## 核心概念

### 1. 样本不一定等于分子

模板说明“一行代表一个粘合剂配方/样品”。一个配方可能包含主树脂、固化剂、添加剂和不同配比，因此不能把某一个组分的分子图直接叫作“这个配方的图”。

### 2. 名称不等于结构

商品名、内部代码、化学体系和官能团名称都不能自动转换成唯一可靠的分子结构。结构至少需要可解析表示、来源、版本和领域人员确认；商业混合物还可能不存在单一 SMILES。

### 3. 字段存在不等于证据就绪

模板存在“实测性能名称/值/单位”三列，但当前没有数据行，也没有性能测试方法字段。此时目标值覆盖率和可比性都不能计算。

### 4. 门槛评审先于建模

今天检查七项：

| 门槛项 | 最低证据 | 当前模板事实 |
|---|---|---|
| 真实样本 | 至少有获准使用的真实记录 | 实际样本为 0 |
| 一致实测标签 | 首要目标、单位和测试方法一致 | 有标签模板，但非空标签为 0 |
| 结构来源与覆盖率 | 结构可解析、来源可追溯、覆盖率可计算 | 无结构与来源字段，0 样本下不可计算 |
| 样本与图对象 | 一行和一张图分别代表什么已冻结 | 空白模板不能确认 |
| 多组分表示 | 组分、结构、配比能在同一样本关联 | 只有名称/配比模板，无实际记录和结构 |
| 权限 | 结构与实验数据的建模使用权限明确 | 未提供样本级授权证据 |
| 基线 | 同一数据划分上有可复现的简单基线 | 0 样本，不能建立基线 |

## 核心代码/核心文档

Notebook 自动从当前工作目录向上寻找仓库根目录，不写死任何人的机器路径：

```python
from pathlib import Path

def find_repo_root(start=None):
    start = (start or Path.cwd()).resolve()
    for candidate in (start, *start.parents):
        source = (
            candidate
            / "data"
            / "adhesive"
            / "templates"
            / "粘合剂重要化学性质_数据格式_v0.3.xlsx"
        )
        if source.is_file():
            return candidate
    raise FileNotFoundError("未找到仓库中的真实 v0.3 Excel。")

repo_root = find_repo_root()
source_path = (
    repo_root
    / "data"
    / "adhesive"
    / "templates"
    / "粘合剂重要化学性质_数据格式_v0.3.xlsx"
)
```

实际读取必须保留 `header=3`，因为 pandas 从 0 开始计数，`3` 对应 Excel 第 4 行：

```python
import pandas as pd

table = pd.read_excel(
    source_path,
    sheet_name="01_核心化学性质",
    header=3,
    engine="openpyxl",
)
actual_table = table.dropna(how="all")
```

最终决定只允许由门槛证据产生：

```text
七项证据全部满足，且完成导师、化学组和数据负责人审批 → Go
只有能够补齐的证据缺口                              → 补数据后 Go
图对象不成立、结构不可得或权限不允许等硬阻塞          → No-Go
```

以当前真实空表运行时应得到 `No-Go`。Notebook 的自动检查只负责暴露缺口，不能自行签发 `Go`；未来补齐证据后仍需三方人工复审。

## 常见错误

- 把 Excel 中格式化的 100 个预留行当成 100 条样本；
- 忘记 `header=3`，把说明文字当表头；
- 把“主树脂/基体名称”当作 SMILES；
- 为了演示而自己填写分子式、结构、配方或性能；
- 看到公开参考链接就推断项目样本已获得使用授权；
- 用随机行划分，让同一配方或近重复配方跨训练集与测试集；
- 在 0 条样本上讨论 GNN 是否优于随机森林；
- 把 `No-Go` 误解为“以后永远不能用 GNN”。
