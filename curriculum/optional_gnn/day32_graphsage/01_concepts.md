# Day 32.1：GraphSAGE、mean 聚合与公平比较

## 1. GraphSAGE 在做什么

GraphSAGE 的核心仍是消息传递。对节点 `i`，一层常见的 mean GraphSAGE 可以直观写成：

```text
邻居摘要_i = mean(所有邻居的当前表示)
新表示_i = 激活(
    自己的表示 × 自身权重
    + 邻居摘要_i × 邻居权重
)
```

它把“自己”和“邻居平均值”分别做可学习变换。GCN 则按带度数归一化的规则共同聚合自己和邻居。

两者都使用 `x` 与 `edge_index`，但内部计算不相同。

## 2. mean 聚合不是拼接所有邻居

假设一个节点有三个二维邻居表示：

```text
[1, 2]
[3, 4]
[5, 0]
```

mean 聚合结果：

```text
[(1+3+5)/3, (2+4+0)/3] = [3, 2]
```

无论这三行的输入顺序如何，平均值不变。这叫做“对排列不敏感”。

图中的邻居没有天然的第一、第二、第三名，因此聚合函数通常必须对邻居排列不敏感。否则同一张图仅仅更改边的存储顺序就可能改变含义。

## 3. GraphSAGE 与邻居采样

GraphSAGE 常和邻居采样一起出现：

- 大图中，一个节点可能有大量邻居；
- 每层只抽取固定数量的邻居，可以控制计算量；
- 多层采样形成一个局部计算子图。

邻居采样不是“随机删边后假装图变了”，而是训练时为了计算效率选择本次参与聚合的邻居。Day 32 的 KarateClub 很小，因此使用完整邻居，不启用采样。

## 4. 当前实验仍是传导式

GraphSAGE 的重要优势之一是其聚合函数可以用于此前未见的新节点。但今天：

- 训练时完整 KarateClub 图的节点特征与边可见；
- validation/test 标签被掩码；
- 没有构造真正的新图或未见节点测试。

所以本日结果不能证明“归纳泛化能力”。它只比较两个算子在同一传导式教学协议下的表现。

## 5. 两层 GraphSAGE 的 shape

```text
x                   [N, F]
SAGEConv(F, 16)  →  [N, 16]
ReLU             →  [N, 16]
Dropout          →  [N, 16]
SAGEConv(16, C)  →  [N, C]
```

GraphSAGE 与 GCN 的接口和输出 shape 可以相同。这让“只替换模型类”的实验设计成为可能，但不表示两个模型内部算法相同。

## 6. 为什么要使用配对种子

神经网络的结果受随机初始化和 Dropout 影响。只运行一次可能出现：

```text
seed 7：GCN 较高
seed 17：GraphSAGE 较高
```

配对种子表示两个模型都运行相同的 `7、17、27`：

| seed | GCN | GraphSAGE |
|---:|---:|---:|
| 7 | 一次结果 | 一次结果 |
| 17 | 一次结果 | 一次结果 |
| 27 | 一次结果 | 一次结果 |

它减少“模型 A 恰好使用幸运种子、模型 B 使用不幸运种子”的混淆。

三种种子仍然很少，只能作为教学级稳定性观察，不能提供可靠的统计显著性结论。

## 7. 均值与样本标准差

validation mean：

```text
三次 validation accuracy 相加 / 3
```

样本标准差描述三次结果的波动。Pandas 中：

```python
result.groupby("model")["valid_accuracy"].agg(["mean", "std"])
```

默认 `std` 使用 `ddof=1` 的样本标准差。

- 均值较高：在这几次运行中平均表现较好；
- 标准差较大：结果对随机性更敏感；
- 均值略高但差距小于波动：不应轻率宣布胜者。

## 8. 参数量与公平性

`GCNConv(F, H)` 与 `SAGEConv(F, H)` 的参数化不同。GraphSAGE 通常分别变换自身与邻居摘要，因此即使 `H` 相同，参数量也可能更多。

本日公平性是：

```text
相同数据 + 相同划分 + 相同表示宽度
+ 相同训练预算 + 相同种子
```

它不是：

```text
严格相同参数量 + 为每个模型单独充分调参
```

必须把这个限制写进结论。

## 9. 为什么不比较墙钟时间

在 34 个节点的教学图上，毫秒级时间会受到以下因素影响：

- 首次导入和缓存；
- CPU 线程调度；
- 后台程序；
- PyTorch/PyG 版本；
- 当前机器硬件。

因此 Notebook 不持久化墙钟时间，也不据此排名。未来需要效率研究时，应使用预热、重复、同步设备和明确硬件的基准协议。

## 10. 今天不能得出的结论

- 一次或三次 validation 结果不能证明一个算法普遍更好；
- GraphSAGE 名字中有 “sample”，不表示本次已经做了邻居采样；
- KarateClub 结果不能迁移为分子或下游任务结论；
- validation 比较不能代替最终 test；
- 参数更多不必然更好，参数更少也不必然更差。
