# 教学与自学指南

这份指南面向两类使用者：独立学习者，以及希望把本仓库用于读书会、研究生入门课或组内培训的带领者。

## 教学目标

课程不是算法名称清单。每个单元都围绕四层能力设计：

| 层级 | 学习者应做到什么 | 典型证据 |
|---|---|---|
| 识别 | 说出术语和模块作用 | 自测、术语解释 |
| 推演 | 用小例子手算或画出流程 | 误差表、伪代码、流程图 |
| 实现 | 从空内核运行并修改最小代码 | Notebook、断言、输出文件 |
| 判断 | 解释结果与证据边界 | `notes.md`、阶段报告、反例 |

只完成“实现”而没有“判断”，不算完成本课程的研究训练目标。

## 推荐的一次课结构

以 90–120 分钟为例：

1. 10 分钟：用一个错误结论或小问题说明为什么要学；
2. 20 分钟：阅读概念并让学习者复述；
3. 20 分钟：纸笔推演，不打开参考答案；
4. 25 分钟：从空内核运行 Tutorial，预测每段输出后再执行；
5. 20 分钟：独立练习或两人互审；
6. 10 分钟：写“能说明 / 不能说明”和下一步。

内容较重时，应把一个 Day 拆成两次，而不是跳过推演或验证。

## 提问方式

比“代码跑了吗”更有效的问题：

- 这一步的输入、变换和输出分别是什么？
- 哪些量来自训练数据，哪些量来自验证数据？
- 如果删除这个基线，结论会失去什么支撑？
- 哪一行代码会在真实标签不可见时造成泄漏？
- 结果变好是算法原因、划分原因还是随机波动？
- 当前证据能迁移到真实下游任务吗？为什么？

## 统一验收量表

每个维度按 0–2 分评价，总分不是为了排名，而是定位缺口。

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 概念 | 不能解释 | 能复述定义 | 能用反例或对比解释 |
| 数据边界 | 混用 train/valid/test | 知道规则但不能定位代码 | 能审计每一步标签权限 |
| 代码 | 不能独立运行 | 能运行但依赖照抄 | 能修改并解释影响 |
| 验证 | 只报单个分数 | 有基线或多次结果 | 协议公平且保留逐次证据 |
| 结论 | 过度外推 | 有限定语 | 明确能说明、不能说明和下一实验 |

建议完成标准：没有任何 0 分；总分至少 8/10；“数据边界”和“结论”必须为 2 分后，才进入真实下游任务实验设计。

## 如何使用参考答案

参考答案用于核对，不用于第一次作答。推荐流程：

1. 学习者先提交自己的答案或口头解释；
2. 标出不确定项；
3. 再打开 `04_reference_answers.md`；
4. 不只改成正确答案，还要写清原先错误的原因；
5. 若答案与运行结果冲突，以可复查定义和代码证据为准，并提交修订。

## 如何处理预存 Notebook 输出

课程 Notebook 的预存输出是“教材可运行”的证据，不是学习者完成的证据。学习者应从空内核运行，并在本地 `learning_outputs/` 中填写：

- 本次输入；
- 做了什么变换；
- 输出和检查；
- 与预期是否一致；
- 结果能支持什么；
- 结果不能支持什么。

可用状态工具记录开始和完成，但它不会替代教师或学习者的理解验收。

## 阶段性项目建议

### Day 1–7 后

给一张小表，让学习者选择指标和两个基线，并口头解释。重点不是高分，而是变量、单位和误差。

### Day 8–14 后

要求提交预注册协议、逐折结果、汇总表和一页报告。故意加入一个预处理泄漏示例，让学习者指出问题。

### Day 15–24 后

在完全相同输入和划分下比较 Ridge、随机森林、MLP 和 OOF Stacking。允许复杂模型不获胜。

### 主动学习 Unit 1–9 后

要求提交固定候选池、多策略同预算比较、逐轮日志、Random 基线、学习曲线、标签权限审计和 Oracle 证据等级说明。

## 课程维护原则

- 新概念先用最小人工数据验证，再接真实公开数据；
- 每个模型至少有 Dummy 或简单模型基线；
- 教学输出与学习者输出必须分开；
- 参考答案与练习文件必须分开；
- 不在练习题正文中直接填写答案；
- 不用 test 结果指导教材中的模型选择；
- 数据、版本、种子、划分和指标必须可追溯；
- 任何材料结论都要与证据等级一致。
